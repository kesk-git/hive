# Test targets

Each package proves itself through its own target, and the calls between packages are proved separately. This file names every target, says what it runs and what it must prove, and fixes the rules all of them follow. The targets are entries of the root `Makefile`; none exists until the build creates it.

Owner: each package owns its target; the contract library owns `test-contract`; the repository owns the rest.

The seven package targets and their scopes are the design's. What each must prove grows with its stage: a stage adds its proofs to its package's row here in the change that defines its contracts.

## Rules for every target

1. **Independent.** A package target builds that package and the contract library it depends on, and runs that package's tests and no others; the contract library's own tests belong to `test-contract`. It passes or fails the same whether or not any other package exists, builds or passes. Where a package calls another, its own tests stand in a fake for the other's command, built from the other's declared schemas; the real call is `test-integration`'s to prove.
2. **Named in full.** The `Makefile` lists each target and each package directory by its full name. No target is derived from a pattern, and none selects by a suffix; see [naming.md](naming.md#keeping-it-apart-from-the-pool).
3. **No network, no model, no account.** No target contacts a network, starts a model turn, reads a credential or touches an account. A test that needs `gh`, `claude`, `codex` or the platform utility `security` runs a recorded fake that the test itself places first on the search path; every fake is an executable the test builds from Go, never a script, so that the lookup rules of [the one process-execution path](distribution.md#finding-the-program) find it on all three platforms. A test may run the real `git`, against repositories it creates. The real behaviour of each platform's credential store, the keychain on macOS, Credential Manager on Windows and the Secret Service on Linux, is a qualification on that platform outside the targets, like the qualification of an execution route; the design lists it under its implementation evidence still required.
4. **No private home, no real clone.** Every test creates the homes, clones and worktrees it uses under a temporary directory and removes them. No test reads or writes an existing private home, an existing worktree pool, a project's clone or any state of an existing installation.
5. **Deterministic.** A test that depends on time takes the clock as an input. A test of concurrency runs its interleavings by control, not by sleeping and hoping.
6. **One command each.** Each target is one command from the repository root with no argument and no environment to set, the same command on each of the three platforms, exits 0 on success, and prints the name of each failing test otherwise.
7. **Bounded.** A Hunt's declared checks at a head complete within ten minutes on the operator's machine and any one target within five, each measured from the command's start with no wait for a lock counted, apart from a long run that is the Hunt's own evidence, as the design's [How Hive tests](../docs/design.md#how-hive-tests) states. A target that outgrows its bound is split by the package's owner or declared long in Hive's [test contract](#a-projects-test-contract), and then runs at the landing that completes a Target; it is never skipped.
8. **A target that has nothing to run fails.** A target whose package holds no test exits nonzero, so an empty package cannot pass by default. Hive's test contract marks such a target not built, and the gate command runs the built targets only.
9. **Three platforms.** Every target passes on macOS, Windows and Linux, and a pass on one establishes nothing about the others. The macOS runs take place on the operator's own Mac. GitHub's hosted Windows and Linux runners, for this public repository, are Hive's declared test environment for those two platforms, by the operator's decision: they run the targets there and report the results, which are evidence of a remote producer that the gate reads under the design's [hybrid on evidence](../docs/design.md#synapse-on-the-operators-machine-with-both-reviewers), and never the gate, whose verdict and merge stay on the operator's machine. One workflow file under `.github/workflows/` runs `make test` on both for every Harvest head and every night; its results are required at the landing that completes a Target and in the scheduled run, and are informational at every other head: at a Hunt's landing a red one is recorded as a finding on the Hunt and the Hunt lands, and no ruleset of this repository names them as required, so the forge never blocks a Hunt on them. A test whose behaviour depends on the platform states what it expects on each of the three, and no test passes on a platform by being skipped there.

## A project's test contract

Each project declares its tests in one file at the root of its repository, owned by the project and kept there as what tests the application, as the design's [How Hive tests](../docs/design.md#how-hive-tests) states. It is a record kind of its own, described here in prose; its schema enters with stage 5, the first stage that reads it, as a minor change. Beside the project-level commands the gate already runs, build, format, lint and smoke, it holds one row per test:

| Field | Content |
| --- | --- |
| `name` | The test's name, unique in the file, which a receipt names; for Hive, the `make` target's name. |
| `command` | One command from the repository root, with no argument and no environment to set, which exits 0 on a pass, as rule 6 asks of a target. |
| `class` | `check` or `long`: a Hunt's check at a head runs the checks it affects, and the landing that completes a Target runs the long tests. |
| `reads` | The paths and globs the test reads, its own files included; `**` for everything. |
| `bound_seconds` | The time within which the test must finish on the operator's machine, measured from the command's start: a wait for a lock is not counted. |
| `needs` | Any of `quiet`, a quiet machine; `display`; `whole-machine`; and `network`, which Hive's own tests never name. |
| `platforms` | The platforms the test must pass on; every row of Hive's own names all three. |
| `status` | `built`, or `not-built` for a target whose package holds no test yet. |

The file carries declarations only, and nothing a run produced. A test's measured time, its last result and its count of re-runs are receipts in the home, written by the scheduled run and by the gate, whose kinds enter with this record's schema at stage 5. They are not fields of the committed file: a measurement records a run, which rule 11 of the [layout](layout.md#rules) keeps out of a repository, and a field for one would have Hive commit to a project's repository at every scheduled run.

Three rules follow from it, and every set the gate runs is computed from them:

1. **The affected set.** A test is affected at a head when its `reads` meet a path of `git diff --name-only --no-renames -z` between the head of its last recorded pass and that head, which lists a rename's source and its destination as two paths, each NUL-terminated so that no filename is misread. A changed path that no row declares affects every test, and so do this file, the build files (`Makefile`, `go.mod`, `go.sum` or a project's own) and a lockfile; a test that uses a helper declares it in its `reads`.
2. **A pass carries.** A pass is a receipt per test per head. It carries to a later head whose affected set leaves the test out, and the receipt names the head the test ran at and that the comparison found nothing.
3. **Long by measurement.** `class` follows the test's invocation on the operator's machine: it is `long` when the receipts of the test's runs measure it past the bound for one test, when `needs` names anything, or when `platforms` leaves out the operator's machine, so that the test has no local invocation. A row that names the other platforms beside the operator's machine stays `check`: the Windows and Linux results are a separate obligation, required at the landing that completes a Target and in the scheduled run and informational at every other head, as rule 9 states. A project may declare a test long by hand; nothing declares one short by hand.

Hive's own test contract holds these rows, and by rule 1 a change to a build file affects every one of them:

| `name` | `command` | `class` | `reads` | `bound_seconds` | `status` |
| --- | --- | --- | --- | --- | --- |
| `check` | `make check` | `check` | `**/*.go`, `spec/schemas/**` | 60 | `built` |
| `test-contract` | `make test-contract` | `check` | `contract/**`, `spec/**`, `**/*.go`, `packages/*/hive-package.json` | 300 | `built` |
| `test-pool`, `test-spawning-pool`, `test-word` | `make test-<package>` | `check` | `packages/<package>/**`, `contract/**`, `spec/**` | 300 each | `built` |
| `test-dispatch`, `test-shadow`, `test-synapse`, `test-ui`, four rows | `make test-<package>` | `check` | `packages/<package>/**`, `contract/**`, `spec/**` | 300 each | `not-built` |
| `build` | `make build` | `check` | `**/*.go`, `spec/schemas/**` | 120 | `built` |
| `test-integration` | `make test-integration` | `check` until measured | `**` | 300 | `not-built` |
| `test-distribution` | `make test-distribution` | `long`, needing the whole machine, on all three platforms | `**` | 900 | `not-built` |
| `check-imports` | `make check-imports` | `check` | `**` | 60 | `not-built` |
| `windows`, `linux` | the workflow's `make test` on each | `long`, on that platform | `**` | 900 | `not-built` |

The scheduled full run runs every row with every cache defeated, `go test -count=1` for Hive, each test alone in this file's order, and records each test's measured time and last result as receipts in the home. It writes nothing into this file.

## What the targets do not cover

A project's own test, build and lint commands belong to that project's validation configuration. Hive's targets validate Hive and are never a substitute for them.

The end-to-end proof of stage 7, the qualification of each execution route and the measurements the design asks for are separate work with their own evidence. They are named in the design's list of implementation evidence and are not targets of this file.
