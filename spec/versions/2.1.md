# Version 2.1

Version 2.1 follows the first group of the Pool memory definition with tier-and-role projections, render/check/propagate bodies, retained rendering and receipt inventories, and per-subject independently sourced misses.
[pool.md](../pool.md) owns startup loading, step-command loading, freshness, each projection's budget and the second-independent-miss decision.
The projection record and incompatible memory operation bodies use their v2 schemas; the miss record and miss operation bodies start at 1.0.
The Pool declaration, read alternatives and complete fixtures change in this same group, and word.md points to the Pool's subject-origin question deduplication rule.

This is the next minor contract version of the ordered major definition begun at [2.0](2.0.md).
The new kinds and operations add to that definition, and the v2 projection contracts retire their unbuilt v1 predecessors and deferrals because no record of those versions can exist.
No migration or preservation format is needed for a nonexistent source.
No projection schema remains deferred after this group; the ten still-current rule/specification deferrals stay.
Every changed record retains its canonical owner, and no package or dependency moves.
The inherited and own Fleet projections retain separate budgets, and workers receive subject projections only inside their Imperative.
