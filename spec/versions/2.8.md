# Version 2.8

Version 2.8 states, in [pool.md's Admission](../pool.md#admission), how admission verifies a request's `rule` authority for one sensitive boundary: the rule must be the Hive Mind's own sentence recorded as a rule, its subject must name that boundary, it must be in force at the check's instant and its scope must contain the admission's, and it clears only the boundary its subject names. It also states that an approval on the record or the request's own `word` authority is verified again at every check, at the scope of the admission.

No schema's shape changes and no operation, member, record or error code is added. This is a minor change under [Changing a contract](../README.md#changing-a-contract): it states a route the contract already named as verifiable, and every request and record valid before the change is valid after it.
