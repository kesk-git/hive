# Version 1.12

Version 1.12 states, in the [layout](../layout.md#rules) and in the design, what a repository may hold and how a Harvest and a commit read, for Hive's own repository and for the projects Hive runs. Rule 11 of the layout becomes the landing test, three questions of reader, tense and exposure applied to every path a change adds or changes and to the Harvest body and the commit messages; a path that fails the first two moves to its owner in the private home, a line that fails the third is rewritten first, and a version note is the one record that stays. The layout lists the repository's `.claude/settings.json` as configuration, with its one setting that keeps the AI co-author trailer off, and a new rule 13 states that no AI watermark appears: no AI co-author or session trailer in a commit or a merge commit, and no generated-by line in a Harvest, a comment or a file. The lane note `.agents/notes/hive-s1-2a.md` is removed, and git history keeps it.

The design states what a Harvest's body carries in [what a Harvest and a commit say](../../docs/design.md#what-a-harvest-and-a-commit-say): what changed, the risk, the testing and the gate's findings, as the requirement and the outcome and never as a quotation of the Hive Mind, and the same for every commit message. Assimilation lands a Harvest by squash and writes the squash message itself. The knowledge port keeps pending notes in the private home, never in a project repository. The cloud recipe of [Claude in the Void](../../docs/design.md#claude-in-the-void) no longer relies on the session trailer: the collection record binds a branch to its session by the session ID, the launch time and the branch created after the launch; collection reports a commit that carries an AI co-author or session trailer as a finding; and the project's repository settings drop the session trailer with `attribution.sessionUrl` set to false, beside `includeCoAuthoredBy` set to false.

No schema changes. It is a minor change by the rule of [spec/README.md](../README.md#changing-a-contract) and the precedent of 1.7, 1.10 and 1.11: it changes the prose of the layout and of the design and adds no member, no operation, no code, no record kind, no package and no dependency; every record and declaration valid under 1.11 is valid under 1.12; and it asks nothing of code already built, so the library's contract version constant does not move.
