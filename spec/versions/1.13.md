# Version 1.13

Version 1.13 states, in the design and in the contracts that own each part, where Hive keeps its records, how the gate takes its evidence, what Quit does and the items the design had left for later. Every record Hive keeps on a machine sits in one folder, Hive's root, which is the platform's own place for an application's data unless the Hive Mind names another folder: the Hive's home is `hive/` in it and each Fleet's home a directory under `fleets/`, each in the landed layout of plain JSON files, and nothing of Hive's is kept inside a project. [records.md](../records.md#the-home) states how the root is found on each platform, and [decision 8](../decisions.md#8-requests-never-travel-as-arguments-and-the-home-is-always-named) still holds: the root is resolved where Hive is started, and every command takes its home from `--home` alone. The gate is a hybrid on evidence: its verdict, custody, fix writer and both reviewers are on the operator's machine, and a remote producer a project declares, GitHub's hosted runners for Hive's own Windows and Linux targets among them, reports head-bound results that the gate reads as that producer's evidence, through the plugin's ci step on the Harvest route; [distribution.md](../distribution.md#platforms) and [test-targets.md](../test-targets.md#rules-for-every-target) rule 9 now read the runners as such a producer. Quit stops Hive after showing what runs: a stop intent for the Hive and every Fleet, local agents parked at a safe checkpoint, every session host and the Shadow ended, and a cloud session left running for collection at the next start. The app notifies on Windows from its own icon in the notification area, with nothing registered; an approval the Hive's own session asks for shows in the dock as a message of its own kind and is notified like a decision; Waiting on you lists each review awaiting the Hive Mind's round apart from the decisions; and the review surface has no layout-issue inbox, whiteboard or public publishing. An artifact under review is a mockup, a report, a plan, a comparison or a decision page; it is self-contained, with no remote reference and no network in its frame; the owner may write and register one for its own task; and a review ended by Done takes no new revision, as [review.md](../review.md) now says. The Hive Mind reaches an agent only through its supervisor, and the session host's join operation is a read-only view. The app checks Hive's setup at every launch, and every failed check is repairable from inside the app on the Hive Mind's press, which is the one way Hive installs, upgrades or configures a dependency. Codex Cloud is out of Hive's scope rather than parked: `codex-cloud` stays a named value that admission refuses with `pool.placement_parked`, and its label reads Codex Cloud (out of scope). [decisions.md](../decisions.md#left-to-the-stage-that-needs-it) narrows three open points and adds one, [session-messages.md](../session-messages.md#what-is-not-defined-here) points to the design for what an approval shows, and the stale open point of [pool.md](../pool.md#left-undecided) on how a value is recognized is closed, since the design's Secrets section states it.

When a project is registered, Hive asks the Hive Mind which systems or devices the project must run on beyond the machine it first runs on, and from when, and records the answer as the project's ruling, a rule record at the project's scope that [pool.md](../pool.md#rules) now names; the design states it in [A project's systems, asked at intake](../../docs/design.md#a-projects-systems-asked-at-intake). A later decision, dependency, contract or Imperative that narrows that list, or leaves a listed system with no test run, goes to the Hive Mind as its own question, with the cost of undoing it once landed, before a Hunt builds on it, and a clash with the Hive Mind's unsuperseded words is never settled by reading them down.

The design states [How Hive tests](../../docs/design.md#how-hive-tests): a Hunt's check at every head, the Target's long tests once at the landing that completes it, and a scheduled full run of main as the net, each set computed from the project's test contract and never judged. [test-targets.md](../test-targets.md#a-projects-test-contract) adds that contract, one file at a project's repository root with a row per test, its command, class, reads, bound, needs, platforms, measured time and status, its three rules for the affected set, the carried pass and a test long by measurement, and Hive's own rows. A Hunt's declared checks are bounded at ten minutes and any one test at five, measured from the command's start without lock waits and apart from a long run that is the Hunt's own evidence, which rule 7 now states, and a check that outgrows its bound is split by its owner or declared long and runs at the Target's landing; the declared test commands, run from the project's trusted configuration, are the test result in both directions, and a model's verdict on the tests is a finding ruled on its evidence, never a pass over a red command; the Windows and Linux runner results are required at the landing that completes a Target and in the scheduled run, informational at every other head, which rule 9 now states with the one workflow file that [layout.md](../layout.md) lists under `.github/workflows/`; a red scheduled run of main, after one re-run of a timing red, files its fix at once and holds every Target landing of that project until a run of main at or after the fix is green; and every scheduled run records each test's measured time, class and last result, shown where the schedule is, a test re-run more than twice in fourteen days marked flaky.

The eight dispatch classes stay, and each has a playbook of its own, its steps, its checks and its stopping point: rule records at the Hive's scope whose roles name the class, which `hive-imperative render` writes into the Rules section of every Imperative of that class, after the Boundary, as [pool.md](../pool.md#the-imperative) now states; a conflict among them refuses the rendering with `pool.rule_conflict`, and the dispatch matrix still maps a class to its profiles and placement only. A worker settles an ambiguity inside the accepted specification and its Boundary and lists each ruling instead of stopping, and every Hunt's final message is a short contract of status, commits, one line of test evidence, concerns and report path; a fresh Lictor, never the author, checks every definition for what a builder would still have to guess before the Fleet accepts it, and a definition names what each Prey consumes and produces and the inputs no test names; a review returns what it set aside beside its findings; a class 6 repair stops after its third failed fix; the proof rule stays red before green in either order, with no test-first order mandated and three test lines added; and from a validation run's third review round, which is its second fix turn, every review-fix turn runs on the dispatch matrix's step-up member, one tier up in the fixer's own vendor and never across vendors, held in the matrix's gate entry and the gate's configuration together, which changes who fixes and never how many rounds run or the fifth-round signal. The design states these in [Eight dispatch classes](../../docs/design.md#eight-dispatch-classes), [Render and deliver the Imperative](../../docs/design.md#render-and-deliver-the-imperative), [Definitions, standing rules and generated knowledge](../../docs/design.md#definitions-standing-rules-and-generated-knowledge) and [Fix rounds and completion](../../docs/design.md#fix-rounds-and-completion).

No schema's shape changes: the descriptions of the request and the response of `hive-imperative render` say what a rendering now holds. `pool.rule_conflict`, which `resolve` reports, is also the code with which `render` refuses. The version adds one record kind, a project's test contract, described in prose, whose schema enters with stage 5, the first stage that reads it. It is a minor change by the rule of [spec/README.md](../README.md#changing-a-contract) and the precedent of 1.7, 1.10, 1.11 and 1.12: it changes the prose of the contracts and the design and the text of one label, adds a new kind, which an existing reader can ignore, and adds no member, no operation, no package and no dependency; every record and declaration valid under 1.12 is valid under 1.13. It asks of code already built one addition, the contract library's function that resolves Hive's root, which no built test contradicts and which the lane that builds it adds; until then the library's contract version constant stays at the last version whose demands the build meets.

Version 1.13 lists the repository's `.no-mistakes.yaml` in the [layout](../layout.md), beside `.claude/settings.json`, as repository configuration for the validation pipeline. The file holds the one fixed gate command: `make check` and then every built target, which today are `check` and `test-contract`. No model chooses what runs, and the declared command's result is the test result; a model's verdict on the tests is only a finding.

The gate command is not `make test` whole. `make test` is the check of the finished repository: by [rule 8 of the test targets](../test-targets.md#rules-for-every-target) a target whose package holds no test fails, so `make test` fails for as long as any package target, `test-integration`, `test-distribution` or `check-imports` has nothing to run, and `build` passes while it builds nothing. A target is built once it has something to run and passes; the change that makes a target built adds it to the command in the same change, and `make test` becomes the gate command when every target is built.
