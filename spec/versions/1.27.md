# Version 1.27

Version 1.27 makes the design and its contracts agree with themselves in eight places, and names where the gate, its proof and collection run.

A Harvest is opened by the proof-owning publisher in the local flow on the operator's machine, after the required local and Target-head proof, whichever place built the head. A cloud session pushes its collectable branch and its separate status commit and opens none; a Harvest found open earlier is still adopted, as an ordering violation and never as ready at its opening. Claude's hosted GitHub Actions route is enabled for no project Hive manages, since such a project has no pull-request workflow and a hosted-runner workflow only to prove a system the operator's machine cannot; the Claude cloud session stays Claude's place in the Void, and the route's measurement and scope are kept as a record.

A project's [test contract](../test-targets.md#a-projects-test-contract) gains a declared `cadence` per test, `ordinary` or `once-per-target`, the second for a bot, corpus or simulation run, never inferred from a name, command or inputs. It is read before the affected set and before a Hunt's own evidence, and enters the record's schema with stage 5 like every other field. Assimilation decides whether a landing completes its Target when it lands, under a landing boundary every landing beneath the Target shares, and reconciles an uncertain landing first, as [Synapse](../synapse.md#publication-and-assimilation) states; how the boundary and its receipt are represented is stage 5's. A Hunt reaches `published` only on its Harvest's receipt, so a candidate head pushed with no Harvest leaves it at `validating`.

The repair of the active gate's findings stays in the local flow in every general reference, apart from a separately authorized later Hunt, which has a place of its own. The [command contract](../commands.md#invocation) no longer allows a flag or positional short form, and the design's command shapes are illustrative identity arguments. The specification's opening and the design's package table describe the built capabilities-and-refusal scaffolding apart from the behaviour still prospective.

No schema changes. It is a minor change by the rule of [spec/README.md](../README.md#changing-a-contract): it clarifies and extends prospective workflow contracts, moves no ownership, and adds no member to any existing schema, no operation, no record kind, no package and no dependency; every record and declaration valid under 1.26 is valid under 1.27; and no built command offers a short form, so it asks nothing of code already built and the library's contract version constant does not move.
