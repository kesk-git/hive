# Version 2.10

Version 2.10 registers the `miss_` identity prefix that the `pool.miss` schema already requires, and states, in [Generated knowledge](../pool.md#generated-knowledge) of pool.md, how a scoped `check` resolves derivation links and what a link may name.

The prefix is minted by `pool`, in the identity library and in the identity table, so that a miss is given its identity the way every other record of the Pool is.

A scoped `check` reports the subjects with misses in its scope and resolves derivation links against every miss the home retains, wider scopes included, so that an incident whose root lies in a wider-scoped miss is counted as a global `check` counts it. A link may name a miss, or an incident whose retained accounts supply its roots under their current provenance, so that a provenance correction is followed through the links.

No schema's shape changes and no operation, member, record or error code is added. This is a minor change under [Changing a contract](../README.md#changing-a-contract): every request and record valid before the change is valid after it.
