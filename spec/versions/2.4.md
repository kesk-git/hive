# Version 2.4

Version 2.4 states the Pool's four retained refusal rules in [pool.md](../pool.md).
A transition to `done` refuses harvest evidence unless its URL is a full canonical GitHub or Forgejo pull request URL; malformed evidence is `invalid` with `schema_violation` and nothing is written.
An `update` that adds a `blocked-by` edge from an item to itself is likewise `invalid` with `schema_violation` and writes nothing.
An item read whose `states` selector names anything outside `queued`, `in-flight`, `done` and `archived` is `invalid` with `schema_violation`, rather than an authoritative empty result.
The Pool accepts a hold reason with parentheses verbatim, but legacy export refuses an item carrying an in-force hold with a legacy word and such a reason as `invalid` with `pool.legacy_malformed`, whichever hold the entry would otherwise render.

This is a minor change under [Changing a contract](../README.md#changing-a-contract): it clarifies retained validation at the operation boundaries without changing record schemas, accepted schema versions or ownership.
The [specification index](../README.md) and [test targets](../test-targets.md) also correct their built-status wording to refer to each executable's own `capabilities` answer, so the index does not retain a stale list of built operations.
