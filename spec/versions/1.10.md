# Version 1.10

Version 1.10 states the operator's decisions on the platforms that version 1.9 left open, as the design's [Platforms](../../docs/design.md#platforms-native-on-macos-windows-and-linux) section now states them. Every interactive session runs in Hive's own [terminal host](../../docs/design.md#the-terminal-host), a session host of `dispatch`'s on the platform's own pseudo-terminal, joined from the operator's own terminal and resized so that the agent redraws itself; tmux leaves the dependencies, which become five, and nothing replaces it. Hive's screens are its own app, `hive-ui`, drawn by the platform's own web engine and serving its pages from inside the program through its own URL scheme, so Hive opens no network listener, the app none of any kind, and no other device opens Hive. The standard library stays Hive's only library but for two named exceptions, each pinned and each with an import record for every module it brings: go-keyring, inside Tendril's package, for the Windows and Linux credential stores, in no macOS executable, and purego, in `ui`, for the app on macOS and Linux; a module of either never starts a process. The WebKitGTK package and Microsoft's WebView2 loader are accepted as system parts. The app keeps running until the operator quits it, and Hive never starts at login. A Hive command may enrol a secret, holding the value only in memory, and records a redacted enrolment record; Claude Code's login file on Windows and Linux is accepted while only the operator's user can read it; the place `mac` is labelled Local. [distribution.md](../distribution.md), [decisions.md](../decisions.md) (decisions 1, 4, 15 and 16), [test-targets.md](../test-targets.md), [pool.md](../pool.md), [imports.md](../imports.md), [packages.md](../packages.md), [commands.md](../commands.md), [review.md](../review.md), [records.md](../records.md) and [layout.md](../layout.md) say so where each owns it.

Two schema definitions lose the value `tmux`: the core executables of `package.v1` and the executables of an operation in `capabilities.v1`, and the `dispatch` and `shadow` declarations drop it with them. Removing a value would be a major change by the rule of [spec/README.md](../README.md#changing-a-contract), and it is made instead as an amendment in place, by the precedent of 1.5 and 1.7: no build has written or read a package declaration or a capability declaration naming `tmux`, no built test asserts the value, and no command that a build delivers declares it, so no record a build could have written changes; the schema fixtures that listed it lose it with it, so that each still proves the one rule its name gives. The description of the review files' `operator` changes and its shape does not: `private-network` stays among its values and is written by nothing. It is a minor change: it adds no member, no operation, no code, no record kind and no package; every record and declaration valid under 1.9 that a build could have written is valid under 1.10; and it asks nothing of code already built, so the library's contract version constant does not move.
