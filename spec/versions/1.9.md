# Version 1.9

Version 1.9 makes the contracts platform-neutral: Hive is delivered, built and tested natively on macOS, Windows and Linux, never through WSL2 or another compatibility layer, as the design's [Platforms](../../docs/design.md#platforms-native-on-macos-windows-and-linux) section states. It amends decision 16, which ruled Windows out because tmux has no Windows build, and records the operator's decision that GitHub's hosted Windows and Linux runners, for this public repository, are Hive's declared test environment for those two platforms. It states [the one process-execution path](../distribution.md#the-one-process-execution-path) for all three: how a program is found, with no shell and on Windows only as a native executable; how its arguments and its environment are built; how a plain, a terminal and a resident start are made, Windows's through `CreateProcessW` with a job object and, for a terminal, a pseudoconsole; how a run and its whole tree are stopped on each platform; and how every way a run ends maps to the command contract's exit states, which now read an outcome from a complete response and never from an exit code alone. It states the record format's owner-only access, atomic replacement, flushes and locks for each platform's file system; the artefact's names and links on Windows; the platform-utility clause, with `security` macOS's own; that a clone is compared by file identity; and that committed files keep their line feeds in every checkout.

Two common schema definitions change. `absolute_path` also accepts the Windows drive form with forward slashes, which widens it. `home_relative_path` refuses a segment holding a backslash, a colon or another character Windows forbids, one ending in a dot or a space, and a device name Windows reserves, which narrows it. The descriptions of two members of `records/pool.item.v1` say the operator's machine where they said the Mac, and the value `mac` keeps its name. It is a minor change by the precedent of 1.5, 1.7 and 1.8: no build has written a record holding an absolute path, the Windows form was refusable by no build because no Windows build existed, and no record a build can write holds a relative path the narrowed definition refuses; it adds no member, no operation, no code, no record kind, no package and no dependency, and every record and declaration valid under 1.8 that a build could have written is valid under 1.9. It asks of built code what the design's [code follow-ups](../../docs/design.md#assumptions-replaced) list, so the library's contract version constant stays at the last version whose demands the build meets until the lanes that own that code build them.
