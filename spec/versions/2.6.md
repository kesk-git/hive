# Version 2.6

Version 2.6 brings the request schema of `hive-rule record` into line with the refusal the [Rules](../pool.md#rules) section already states: `record` refuses a rule line over 300 characters with `pool.rule_line_too_long`, naming the measured count, the cap and the recorder's three moves.
The request's `rule_line` keeps `minLength: 1` and no longer carries `maxLength: 300`, which made that refusal unreachable: the harness answered `schema_violation` before the operation ran.
The record schema `records/pool.rule.v2` keeps its own cap of 300, so no rule line over the cap is ever stored.

This is a minor change under [Changing a contract](../README.md#changing-a-contract): every request valid before the change is valid after it, and a line over the cap, once invalid by schema, is now refused by the operation with its own code.
