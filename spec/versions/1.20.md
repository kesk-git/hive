# Version 1.20

Version 1.20 revises the design and its workflow contracts as one change.

Projects enter Hive with their no-CI declaration and declared test command already on main. Hosted runners prove only systems the operator's machine cannot, on main, on a schedule and on demand for a Target's final landing head, never on pull requests. Bot, corpus and simulation runs are always long tests: they prove the Target once at its last-Prey head and never serve as a Hunt's check or its own evidence.

The core carries no tool server or third-party skill; harness plug-ins stay outside Hive records, with self-sign-in required and four refused capability classes. The workflow requires a red acceptance-test first commit, scenario-based coverage, concise rulings and explicit uncertain skips, fast pre-checks separate from proof of record, uncapped review under the round-3 bar, and a fixed-metric autoresearch playbook. Rules have no freeze window.

Policy selects supervision and reviewer roles through the dispatch matrix, whose member, vendor, placement and selection-data requirements are explicit. The matrix supports any number of vendors, same-vendor first and second choices and whatever reviewer roles its effective gate names; qualification compares actual results with those configured roles, with no diversity rule. The Pool schema description now calls Codex Cloud out of scope.

This is a minor clarification and extension of prospective workflow contracts. It moves no ownership and changes no accepted record shape: every previously valid record remains valid. The implementation constant stays at the last version whose demands the build meets.
