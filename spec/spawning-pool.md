# Spawning Pool lifecycle contract

Owner: `spawning-pool`. This file strengthens the design’s [adaptation contract](../docs/design.md#fork-and-adapt-preserve-behavior-and-attribution) for acquire, observe and release. It states behavioural acceptance cases without adding a record shape or a command; the implementation stage qualifies them through `test-spawning-pool` on every supported platform. Existing ownership, preservation and receipt requirements remain in force.

**Git preferences and existing slots.** Pool operations isolate lifecycle-affecting Git preferences from ambient user or repository configuration while preserving the operation’s deliberate fetch semantics. Upgrading the adapted source does not repair an already damaged slot: it requires inspection, an explicit repair where authorized, and requalification before reuse. Acceptance: acquire and release with global `submodule.recurse=true` and other hostile lifecycle preferences retain the intended branch, base and fetch behaviour without changing global settings; a slot damaged by an older build stays unavailable after upgrade until its explicit repair passes qualification. Sources: [upstream treehouse/pull/177](https://github.com/kunchenguid/treehouse/pull/177).

**Reciprocal slot identity.** Before any Git mutation, resolve the common directory and verify both directions of the registration-to-physical-slot relationship, including symlink, junction and case handling. An incomplete acquire or mismatched registration is quarantined for reconciliation, never repaired by mutating the repository it happens to point at. Acceptance: a slot points at another checkout’s registration, a registration points back at a different slot, and acquire stops mid-registration; all refuse subsequent Git mutation and preserve both checkouts. Sources: [upstream treehouse/issues/170](https://github.com/kunchenguid/treehouse/issues/170).

**Git owns HEAD and ref locking.** HEAD changes and safety locking use Git’s actual ref backend, with the expected old head protected through the mutation and head, index and worktree read back before success. Loose-ref paths are not an alternative ref or lock API. Acceptance: exercise loose refs and reftable, advance HEAD between inspection and update, and inject a checkout mismatch; stale-head mutation is refused and mismatched head/index/worktree never yields a successful acquire or release. Sources: [upstream treehouse/issues/174](https://github.com/kunchenguid/treehouse/issues/174).

**Observed reusable capacity.** Observe uses the same preservation predicates as acquire and distinguishes reusable slots from idle-but-protected slots and damaged slots. Failed inspection is unknown/damaged with an actionable cause, never clean or reusable capacity. Acceptance: an idle slot with unmerged commits, a corrupt registration and an unreadable Git inspection each contribute no reusable capacity, retain their distinct cause, and cannot be acquired as clean; a verified reusable slot is counted and acquired by the same predicates. Sources: [upstream treehouse/issues/176](https://github.com/kunchenguid/treehouse/issues/176), [upstream treehouse/issues/142](https://github.com/kunchenguid/treehouse/issues/142).
