## (b) Decisions taken on the recorded choices

Each key was recorded as an open choice in earlier rounds and has now been decided. The document is written to the decision.

### `secrets-store-choice-scope`

Decided: the Linux or Windows store choice is recorded in the home, as a record of `dispatch`, one per home. A home moved to another host re-chooses. Standing as written.

### `secrets-void-references`

Decided: an Imperative for a Void session names the Spoors its work needs, by name and purpose, under allowed access; the session resolves them in its own host's store; a Spoor the Void host does not hold is a hold, not a launch. The backend's `probe` establishes presence in the Void host before the launch, recording present, absent or unknown and never a value. Written into the section, "Render and deliver the Imperative", "Claude in the Void" and stage 4 in round 4.

### `secrets-detection`

Decided, in two parts. *The recognizer at the writer*: beyond a value-typed field, the owner's no-value check recognizes a short fixed list of credential shapes that are unmistakable by construction (a vendor's token prefix with its fixed length and alphabet; the armour line of a private key), kept in the contract library's schema package from stage 2's first writer, each entry named, changed only as a contract change; a match is `invalid` with `secret_shape_recognized`, refused whole with nothing written, the refusal naming the field and the shape and never the text; prose that merely mentions a prefix does not match; the list is a floor, and what it does not recognize is kept exactly and is a found copy when found. *The detector after the fact*: an incident is raised on the Hive Mind's or a supervisor's instruction naming a place, or on a package's own report in a response; an external scanner's report is read as an ordinary instruction; Hive runs no scheduled scan. Both written into the section in round 4.

### `secrets-worker-same-user`

Decided: the platform boundary for workers running as the same user is stated and nothing beyond it is claimed. Standing as written.

### `secrets-publisher-env-variable`

Decided: the publication and dispatch identities' tokens reach gh through Tendril's minimal environment, one declared variable in a child environment built from nothing. Standing as written.

### `secrets-ui-session`

Decided: the UI session's authentication material is minted in memory for one run of the server, never written, shown or handed to a page, and is no Spoor. The text holds either way and stands as written.

### `secrets-order`

Not applicable. No stage or package ownership moved. The Spoor record, presence check, status projection and incident receipt enter with `dispatch` at stage 4; Tendril, the value type and the keychain adapter enter the contract library at stage 4; the shape list enters the contract library's schema package at stage 2 with the Pool's first writer; the `spoor_` prefix is registered at stage 2 with the Imperative; the publisher's Spoor enters `synapse` at stage 5 and the status surface enters `ui` at stage 6. The no-value check is closed schemas and the shape list from stage 2, with the value type added at stage 4; the store as built changes nothing.
